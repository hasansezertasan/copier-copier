# Keep LICENSE out of cobo

`.gitignore`, `.gitattributes` and `.editorconfig` are generated by cobo and sealed. `LICENSE` is not, and stays a hand-maintained template (`template/LICENSE.jinja`, MIT or the Apache-2.0 text). `cobo licenses dump` writes its `# >>> cobo:begin >>>` fence into the license file, which would corrupt the text and can defeat license detection, and the MIT text arrives with `<year> <copyright holders>` unfilled. Filling those in breaks the seal, so the file could never pass `cobo check`. Since the copyright line now carries the start year, the author and the contact, there is nothing left for cobo to manage.

## Considered Options

- **Strip the fence at generation time**: yields a clean file, but the seal is gone, so cobo no longer manages it and the extra step buys nothing.
- **Use cobo only as a one-time source for the license text**: possible, but the text changes rarely and is already vendored; it adds a manual regeneration step with no drift check.

# copier-copier

A [Copier](https://copier.readthedocs.io) template that generates `copier-<subject>` template repositories.

## Usage

```bash
copier copy gh:hasansezertasan/copier-copier path/to/copier-<subject>
```

You are asked for a **subject** (for example `pyproject`); the repo is named `copier-<subject>`. The generated repo has:

- `copier.yml` and a placeholder payload in `template/`
- a pytest suite that renders the template and checks `copier update` (`mise run test`)
- GitHub Actions for tests, release-please, PR-title and branch-name linting, plus Renovate config
- `.gitignore`, `.gitattributes` and `.editorconfig` generated by [cobo](https://github.com/hasansezertasan/cobo), plus a weekly drift check
- lint configs and tool pins under `.config/`, with the Python version in a single `.python-version`

`copier.yml`, `template/`, `tests/`, `README.md`, `AGENTS.md`, `pyproject.toml`, `uv.lock`, `cobo.lock`, `.github/release-please-manifest.json`, `.gitignore`, `.gitattributes`, `.editorconfig` and `.python-version` are written once and then belong to you; `copier update` refreshes the rest. `_skip_if_exists` only protects files that already exist, so a file you delete comes back on the next `copier update`. Delete it again in the update PR if you do not want it.

## Adopting in an existing repo

For a `copier-*` repo that already exists, on a branch named `chore/adopt-copier-copier-scaffolding`:

1. Render over the repo, pinned to the latest release tag so `.copier-answers.yml` records a version `copier update` can walk from:

   ```bash
   copier copy --overwrite --vcs-ref=<latest tag> \
     -d subject=<subject> -d description="..." -d author_email=... \
     gh:hasansezertasan/copier-copier .
   ```

   Files in the author-owned list above that already exist are skipped. The rest, including `LICENSE`, `.github/release-please-config.json`, `.github/renovate.json` and the workflows, are overwritten.

2. Delete the seeded files that do not apply, but only ones the render **newly added**: they show as untracked (`??`) in `git status`. Typical candidates are `template/PLACEHOLDER.md` if the repo has its own `template/`, and `pyproject.toml`, `uv.lock`, `tests/` and `.github/workflows/test.yml` if it tests with something other than the seeded pytest suite. A path your repo already had is skipped, not replaced, so it is yours: never delete it. `_skip_if_exists` only protects files that already exist, so copier creates these inside your repo and **recreates them on every `copier update`**; delete them again in each update PR. `template/.copier-answers.yml.jinja` behaves the same way: it is skipped when your payload already has one with that name, and created inside your payload otherwise.
3. Restore what you want to keep, for example `git checkout -- LICENSE .github/release-please-config.json`. A customised `release-please-config.json` or `renovate.json` is overwritten by the seed, and `copier update` would overwrite it again.
4. Replace `.gitignore`, `.gitattributes` and `.editorconfig` with the cobo seeds from a fresh render, for each one your repo already has, since existing files are skipped and the seeded `cobo.lock` tracks all three. Keep your own entries and stanzas below the end fence, then check the seals from a directory outside the repo, so mise does not parse an untrusted `.config/mise.toml` first: `cobo check --lock-file <repo>/cobo.lock`.
5. The seeded `tests/test_template.py` renders with `--defaults` only. If your template has questions without defaults, pass them with `--data=question=value` in its `copy` calls.
6. Append the scaffolding conventions to your `AGENTS.md`, run `mise trust .config/mise.toml && mise run test`, and commit as `chore: adopt the copier-copier scaffolding`.

## Development

```bash
mise install
mise run test
```

This repo applies itself: its scaffolding is kept in sync with `template/` (see `docs/adr/0001-self-hosting-with-skip-if-exists.md`).

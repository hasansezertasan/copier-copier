# copier-copier

A [Copier](https://copier.readthedocs.io) template that generates `copier-<subject>` template repositories.

## Usage

```bash
copier copy gh:hasansezertasan/copier-copier path/to/copier-<subject>
```

You are asked for a **subject** (for example `pyproject`); the repo is named `copier-<subject>`. The generated repo has:

- `copier.yml` and a placeholder payload in `template/`
- a pytest suite that renders the template and checks `copier update` (`mise run test`)
- GitHub Actions for tests, release-please, PR-title and branch-name linting, plus Renovate config
- `.gitignore`, `.gitattributes` and `.editorconfig` generated by [cobo](https://github.com/hasansezertasan/cobo), plus a weekly drift check
- lint configs and tool pins under `.config/`, with the Python version in a single `.python-version`

`copier.yml`, `template/`, `tests/`, `README.md`, `AGENTS.md`, `pyproject.toml`, `uv.lock`, `cobo.lock`, `.github/release-please-manifest.json`, `.gitignore`, `.gitattributes`, `.editorconfig` and `.python-version` are written once and then belong to you; `copier update` refreshes the rest. `_skip_if_exists` only protects files that already exist, so a file you delete comes back on the next `copier update`. To stop a group of files coming back, decline it with an answer: `seed_payload=false` skips the placeholder payload in `template/`, and `python_harness=false` skips `pyproject.toml`, `uv.lock`, `tests/` and the test workflow. Answers are recorded in `.copier-answers.yml`, so `copier update` respects them. A repo adopted before these two answers existed is asked for them on its next `copier update`; answer no for whatever you deleted.

## Adopting in an existing repo

For a `copier-*` repo that already exists, on a branch named `chore/adopt-copier-copier-scaffolding`:

1. Render over the repo, pinned to the latest release tag so `.copier-answers.yml` records a version `copier update` can walk from:

   ```bash
   copier copy --overwrite --vcs-ref=<latest tag> \
     -d subject=<subject> -d description="..." -d author_email=... \
     -d seed_payload=false \
     gh:hasansezertasan/copier-copier .
   ```

   Pass `-d seed_payload=false` when the repo already has its own `template/`, and `-d python_harness=false` when it tests with something other than the seeded pytest suite. Both answers are recorded, so `copier update` does not bring the declined files back.

   Files in the author-owned list above that already exist are skipped. The rest, including `LICENSE`, `.github/release-please-config.json`, `.github/renovate.json` and the workflows, are overwritten.

2. Restore what you want to keep, for example `git checkout -- LICENSE .github/release-please-config.json`. A customised `release-please-config.json` or `renovate.json` is overwritten by the seed, and `copier update` would overwrite it again.
3. Replace `.gitignore`, `.gitattributes` and `.editorconfig` with the cobo seeds from a fresh render, for each one your repo already has, since existing files are skipped and the seeded `cobo.lock` tracks all three. Keep your own entries and stanzas below the end fence, then check the seals from a directory outside the repo, so mise does not parse an untrusted `.config/mise.toml` first: `cobo check --lock-file <repo>/cobo.lock`.
4. The seeded `tests/test_template.py` renders with `--defaults` only. If your template has questions without defaults, pass them with `--data=question=value` in its `copy` calls.
5. Append the scaffolding conventions to your `AGENTS.md`, run `mise trust .config/mise.toml && mise run test`, and commit as `chore: adopt the copier-copier scaffolding`.

## Development

```bash
mise install
mise run test
```

This repo applies itself: its scaffolding is kept in sync with `template/` (see `docs/adr/0001-self-hosting-with-skip-if-exists.md`).

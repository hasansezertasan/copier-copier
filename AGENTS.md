# copier-copier

A Copier template repo. The payload lives in `template/`; everything else is scaffolding. Here the payload is itself a template repo, generated from the `template/` directory (see `GLOSSARY.md`).

## Conventions

- Branch names follow [Conventional Branch](https://conventional-branch.github.io/); commits and PR titles follow [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/). CI enforces both.
- Any lint configs sit under `.config/`, never at the repo root. Tools that cannot read from there live elsewhere: Renovate and release-please in `.github/`, EditorConfig as `.editorconfig` at the root.
- `.gitignore`, `.gitattributes` and `.editorconfig` are generated by [cobo](https://github.com/hasansezertasan/cobo) and tracked in `cobo.lock`. They are seeded once and are yours afterwards: `copier update` never touches them. Edit only below the end fence; choose other boilerplates with `cobo <source> dump … --lock`; refresh with `cobo update && cobo sync`. A hand edit inside the fence breaks its seal and fails `cobo check`.
- Tool versions are pinned in `.config/mise.toml` so Renovate's native `mise` manager covers them. The Python version is the exception: it lives in `.python-version`, which `mise.toml`, uv and Renovate all read (`PYTHON_VERSION` overrides it in mise). It is seeded once and is yours afterwards: `copier update` never touches it.
- Do not add `_tasks` to `copier.yml`: they make the template unsafe and force `--trust`, which Renovate's copier manager does not pass.
- `template/.copier-answers.yml.jinja` (the answers-file template inside the payload) is what lets generated projects run `copier update`. Keep it.
- Run the tests with `mise run test`.

## Keep the Why

This project records the reasoning behind its code with the Keep the Why
skill (https://keepthewhy.com) — the `.keep-the-why` file at the project
root is its config. Before doing anything else in a session, whatever the
first request is about, load the skill: in Claude Code, invoke the
`keep-the-why` skill (Skill tool); in any other agent, install the skill
first (https://keepthewhy.com/installation/), then read its `SKILL.md` and
follow it, including the `references/*.md` files it points to for the
situation at hand. In Claude Code, if the skill is not available on a fresh
clone, install it with `claude plugin install keep-the-why@keep-the-why --scope project`.
